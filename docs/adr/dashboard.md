# ワークスペース・ダッシュボード機能 設計仕様書

## 概要
ワークスペースごとの情報を集約するダッシュボード機能。  
実体はMarkdownファイルとしてアプリ設定ディレクトリ内に保存され、ユーザーが自由にメモ等を記述できる。
本機能最大の特徴は、「独自記法」を用いてタスク一覧や検索結果などをMarkdown内に動的に埋め込める点にある。

## 保存場所のポリシー
- **フロントエンドの責務**: ダッシュボードを開く指示と、特殊なMarkdown記法の描画拡張。
- **バックエンド(Tauri)の責務**: Obsidianのユーザーディレクトリを汚さないよう、Tauriのアプリ設定ディレクトリ（`app_data_dir`等）に `dashboard_{workspace_id}.md` としてファイルを管理する。

## 拡張性・独自記法の設計（Widget Plugin System）
今後、埋め込める機能が増えることを考慮し、以下の設計方針を採る。

1. **記法**: Markdown標準のコードブロックを拡張し、特定のプレフィックスを用いる（例: ` ```obcowa-tasks ``` `）。
2. **パース**: `marked` による変換時、対象のコードブロックを専用のプレースホルダー（`<div class="dashboard-widget" data-type="..."></div>`）に置換。
3. **動的マウント**: プレビュー描画後、`DashboardManager.ts` がDOMを走査し、プレースホルダーに対してSvelteコンポーネント（Widget）を動的にマウントする。

これにより、既存のMarkdownパーサーを複雑化させることなく、新しいWidgetコンポーネントを追加するだけで安全に機能拡張が可能となる。

## モジュール構成
- `src/features/Dashboard/`
  - `DashboardManager.ts` : プレースホルダーの生成、Svelteコンポーネントのマウント/アンマウント（ライフサイクル管理）
  - `widgets/` : 動的に埋め込まれる各種Svelteコンポーネント群
    - `TasksWidget.svelte`
    - `SearchWidget.svelte`

## セキュリティ・安全性について
- **メモリリーク対策**: プレビュー画面が更新（再レンダリング）される際、以前にマウントされたWidgetコンポーネントを確実に破棄（`$destroy()` または `unmount()`）する仕組みを `DashboardManager.ts` に実装する。
- **データ破損対策**: ダッシュボードの保存は既存のエディタ保存フロー同様、一時ファイル経由またはアトミック書き込みを行い、アプリ強制終了時の破損を防ぐ。
- **Obsidianへの影響**: 実体ファイルをアプリ側で隠蔽して管理するため、Obsidian側から見て不明な独自記法ファイルが一覧にノイズとして表示されることはない。
