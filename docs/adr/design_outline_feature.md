# 設計ドキュメント: アウトライン（目次）機能

## 1. 目的と要件
- **目的**: Obsidianのように、エディタの右枠に見出しによる目次を構築し、文書構造の把握と素早いナビゲーションを可能にする。
- **仕様**:
  1. エディタ右側にアウトラインペインを表示する。
  2. 検索バーを設け、見出しのフィルタリングを可能にする。
  3. 見出しをクリックすると、該当の場所へジャンプする（編集・プレビュー両対応）。

## 2. アーキテクチャとファイル構成
Co-locationの原則に従い、エディタに依存する機能として `src/components/Editor/` 配下に機能をカプセル化する。

- **`EditorOutline.svelte`**: 右ペインのUIと検索状態の管理。（状態を親に漏らさない）
- **`outlineUtils.ts`**: Markdown文字列から見出し構造を抽出する純粋関数モジュール。
  - *仕様*: コードブロック（` ``` `）内に記述された `#` を見出しとして誤検知しないよう除外する。
  - *出力データ*: `{ level: number, text: string, lineIndex: number, headingIndex: number }`
- **`Editor.svelte`**: 全体のレイアウト管理と、アウトラインからの `jump` イベントをハンドリングし、エディタ本体またはプレビューへのスクロール指示をルーティングする。

## 3. ジャンプ機能の実装アプローチ（設計上のトレードオフ）
プレビュー画面でのジャンプにおいて、マークダウンパーサーに手を入れて `id` 属性を付与する方式は、DOMPurifyの設定変更などの副作用を伴う。
これを回避するため、本機能では「**見出しの出現順（headingIndex）**」を利用する。
- **プレビューモード**: 描画済みのDOMに対し `querySelectorAll('h1, h2, h3, h4, h5, h6')[headingIndex]` で要素を特定し `scrollIntoView()` を実行。
- **編集モード（textarea）**: 元テキストの先頭から `lineIndex` 行目までの文字数を合算し、`HTMLTextAreaElement.setSelectionRange()` でフォーカスを当てる。

これにより、既存のパーサーロジックを一切壊さずに、正確でシンプルなジャンプ処理を実現している。

## 4. UI/テーマ連携ルール
- 具体的なカラーコードの直書きは禁止。
- 枠線や背景色は `var(--menu-bg)` や `var(--bg-color)` を使用。
- ホバー時のハイライトは `var(--active-highlight-bg)` を使用してObsidian風のシックな操作感を再現する。
