# タスク一覧 ソート機能およびネスト追従機能 設計書

## 1. 目的と要件
- **目的**: タスク一覧画面（`TaskList.svelte`）において、タスクを見出し内で特定の基準（文言、作成日、更新日）でソート可能にする。
- **要件**:
  - タスク文言、ファイルの更新日・作成日でソートできること。
  - Markdown上で字下げ（インデント）されたサブタスクは、ソート時も親タスクに追従して一つのグループとして動くこと。
  - 将来的なインデント表示機能に干渉しない、柔軟なデータ構造とすること。

## 2. アーキテクチャと責務の分離
複雑なロジックをUIから排除し、純粋関数とバックエンド層に分離する。

1. **バックエンド（`task_ops.rs`）**
   - ファイルのメタデータ（更新日・作成日）の取得。
   - タスク行の先頭インデント文字数をカウント（`indent_level`）。
   - ※ここではタスクの親子関係の構築やソートは行わない。
2. **Svelte 純粋関数（`taskService.ts`）**
   - Rustから受け取ったフラットな配列を走査し、`indent_level` を基に親タスクとサブタスクの木構造（グループ）を構築。
   - UIから指定された `SortOption` に基づき、親タスクの単位でソートを実行。
3. **Svelte UI層（`TaskList.svelte`）**
   - ユーザーからのソート条件（UI）の受け付け。
   - `buildTaskTree` の結果をリアクティブに受け取り、DOMを描画。

## 3. データ処理フロー
1. Rustの `get_workspace_tasks` がファイルをパース。
   - `Task { text: "親", indent_level: 0, file_modified: 1690000000 ... }`
   - `Task { text: "子", indent_level: 2, file_modified: 1690000000 ... }`
2. `TaskList.svelte` でユーザーが「文言順」を選択。
3. `taskService.ts` の `buildTaskTree` が実行される。
   - **フェーズ1（ネスト解決）**: インデント情報を元に、子を親の `subTasks` 配列に格納。
   - **フェーズ2（グループ化）**: 見出しやファイル単位で分類。
   - **フェーズ3（ソート）**: 各グループ内で親タスクを文言順で並び替え。
4. UI側に整理されたツリーが返却され、描画される。

## 4. 影響範囲
- **フロントエンド**: `TaskList.svelte` (UI追加), `taskService.ts` (型拡張と純粋関数の更新), `taskService.test.ts` (テスト追加)
- **バックエンド**: `task_ops.rs` (メタデータ取得とインデント計算処理の追加)
- **リスクと緩和策**:
  - ファイル作成日取得のOS依存エラー対策として、取得失敗時は更新日でフォールバックする。
  - ツリー構築ロジックの変更によるデグレを防ぐため、Vitestによる単体テストを厚く記述する。
