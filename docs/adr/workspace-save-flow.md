# ワークスペース保存フローの設計ドキュメント

## 目的
`workspaces.json` に保存されるワークスペース設定（タスク除外設定やタブの状態など）が巻き戻る問題（Race Condition）を防ぐため、保存処理を直列化・一元管理する。

## 設計方針
1. **直接保存の禁止**: 
   各Svelteコンポーネント（UI層）は、Tauriの `invoke('save_workspaces')` を直接呼び出さない。
2. **一元管理と直列化（キューイング）**: 
   ワークスペースの保存は、必ず専用のマネージャー（例: `workspaceManager.ts`）を経由する。
   内部ではPromiseベースのキュー（またはデバウンス）を使用し、前の保存処理が完全に終わってから次の保存処理を実行する。
3. **最新状態の担保**:
   保存キューが実行される際は、キューに入れられた時点のデータではなく、「実行される瞬間の最新のStoreの状態」を取得して保存する。これにより、待機中に複数回設定が変更されても、最終的な最新状態のみが確実に永続化される。

## フロー図
[UI Component] 
  └─> 更新アクション発火 (例: `updateWorkspaceConfig()`)
       ├─> 1. Svelte Store の状態を更新 (UIは即時反映)
       └─> 2. `requestSaveWorkspaces()` を呼び出し
            └─> [Save Queue]
                 └─> ロック確認。待機中なら待つ。
                 └─> 実行時に最新の Store 状態を取得し、Tauriの `save_workspaces` へ送信。
